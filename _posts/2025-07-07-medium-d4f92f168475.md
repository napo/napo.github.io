<section name="bba8" class="section section--body section--first section--last"><div class="section-divider"><hr class="section-divider"></div><div class="section-content"><div class="section-inner sectionLayout--insetColumn"><h3 name="78a8" id="78a8" class="graf graf--h3 graf--leading graf--title">Da <code class="markup--code markup--h3-code">index.html</code> a <code class="markup--code markup--h3-code">index.exe</code>: la magia di PyInstaller e GitHub Actions</h3><p name="be1f" id="be1f" class="graf graf--p graf-after--h3">Ho realizzato una web app con <strong class="markup--strong markup--p-strong">mappe interattive</strong>.<br>Tutto in HTML, CSS e JavaScript.</p><p name="27aa" id="27aa" class="graf graf--p graf-after--p">Funziona perfettamente… <strong class="markup--strong markup--p-strong">quando viene servita da un webserver</strong>.<br>Il problema è che, per ora, <strong class="markup--strong markup--p-strong">non può essere distribuita pubblicamente</strong>.</p><p name="2d77" id="2d77" class="graf graf--p graf-after--p">Le alternative sono due:</p><ul class="postList"><li name="95d7" id="95d7" class="graf graf--li graf-after--p">mettermi a configurare un webserver protetto solo per questa anteprima (no, grazie),</li><li name="9095" id="9095" class="graf graf--li graf-after--li">oppure far sì che si apra con un doppio clic su <code class="markup--code markup--li-code">index.html</code>.</li></ul><p name="7e43" id="7e43" class="graf graf--p graf-after--li">Purtroppo, però, questo secondo approccio <strong class="markup--strong markup--p-strong">non funziona</strong>, vista la complessità del codice JS/HTML e l’uso di <code class="markup--code markup--p-code">fetch</code> per caricare dati.<br>Il browser blocca tutto: fetch falliti, layer vuoti, errori CORS, silenzio stampa.</p><p name="7559" id="7559" class="graf graf--p graf-after--p">Per ragioni di sicurezza, molte funzioni (come <code class="markup--code markup--p-code">fetch</code>) <strong class="markup--strong markup--p-strong">non sono permesse da file locali</strong>.</p><h3 name="0c96" id="0c96" class="graf graf--h3 graf-after--p">È necessario un web server, anche in locale</h3><p name="0400" id="0400" class="graf graf--p graf-after--h3">La soluzione tecnica è semplice:</p><pre data-code-block-mode="1" spellcheck="false" data-code-block-lang="bash" name="658d" id="658d" class="graf graf--pre graf-after--p graf--preV2"><span class="pre--content"><span class="hljs-built_in">cd</span> docs<br />python -m http.server 8085</span></pre><p name="6e24" id="6e24" class="graf graf--p graf-after--pre">Funziona, ma lanciare un comando da terminale non è immediato per chi non ha un minimo di esperienza<br>Serve qualcosa di più accessibile.</p><h3 name="2f37" id="2f37" class="graf graf--h3 graf-after--p">Entra in scena Python</h3><p name="262b" id="262b" class="graf graf--p graf-after--h3">Creo qui uno script <code class="markup--code markup--p-code">start_server.py</code> che:</p><ol class="postList"><li name="53e6" id="53e6" class="graf graf--li graf-after--p">apre un piccolo server HTTP locale (su porta 8085),</li><li name="bec5" id="bec5" class="graf graf--li graf-after--li">avvia il browser sulla pagina giusta.</li></ol><pre data-code-block-mode="1" spellcheck="false" data-code-block-lang="cpp" name="eef2" id="eef2" class="graf graf--pre graf-after--li graf--preV2"><span class="pre--content"><span class="hljs-keyword">import</span> http.server<br /><span class="hljs-keyword">import</span> socketserver<br /><span class="hljs-keyword">import</span> webbrowser<br /><span class="hljs-keyword">import</span> os</span></pre><pre name="3090" id="3090" class="graf graf--pre graf-after--pre">PORT = 8085<br>DIRECTORY = &quot;docs&quot;</pre><pre name="ba16" id="ba16" class="graf graf--pre graf-after--pre">os.chdir(DIRECTORY)<br>Handler = http.server.SimpleHTTPRequestHandler</pre><pre name="6c65" id="6c65" class="graf graf--pre graf-after--pre">with socketserver.TCPServer((&quot;&quot;, PORT), Handler) as httpd:<br>    print(f&quot;Serving at http://localhost:{PORT}&quot;)<br>    webbrowser.open(f&quot;http://localhost:{PORT}&quot;)<br>    httpd.serve_forever()</pre><p name="15d9" id="15d9" class="graf graf--p graf-after--pre">Questo funziona per chi ha Python installato. Ma non tutti ce l’hanno. E soprattutto, molti usano Windows.</p><h3 name="2834" id="2834" class="graf graf--h3 graf-after--p">E se fosse solo un eseguibile?</h3><p name="4c69" id="4c69" class="graf graf--p graf-after--h3">Sì, certo. Uso Linux, però.<br>E qui comincia l’avventura.<br>Potrei installare una macchina virtuale, oppure Wine… o… ma perché complicarsi la vita?</p><figure name="41d0" id="41d0" class="graf graf--figure graf-after--p"><img class="graf-image" data-image-id="1*KGKoZqdR1P0bgH_6Q-Coxg.png" data-width="1024" data-height="1536" src="/assets/images/medium/8a282d5d909ff382.png"></figure><h3 name="92d6" id="92d6" class="graf graf--h3 graf-after--figure">La magia: GitHub Actions + PyInstaller</h3><p name="185c" id="185c" class="graf graf--p graf-after--h3">Con <a href="https://pyinstaller.org/" data-href="https://pyinstaller.org/" class="markup--anchor markup--p-anchor" rel="noopener" target="_blank">PyInstaller</a> posso creare un eseguibile dal mio script Python, ma solo per il sistema operativo su cui lo eseguo.<br>Non ho MacOSX e non ho Windows ma con <strong class="markup--strong markup--p-strong">GitHub Actions</strong> posso tranquillamente automatizzare l’operazione in ciascuno di questi ambienti.</p><p name="be56" id="be56" class="graf graf--p graf-after--p">E la cosa bella è che, ogni volta che effettuo una push (<code class="markup--code markup--p-code">git push</code>), GitHub Actions mi genera automaticamente i tre eseguibili.</p><h3 name="a26f" id="a26f" class="graf graf--h3 graf-after--p">Questo il workflow creato</h3><pre data-code-block-mode="1" spellcheck="false" data-code-block-lang="makefile" name="cd99" id="cd99" class="graf graf--pre graf-after--h3 graf--preV2"><span class="pre--content"><span class="hljs-section">name: Build executables</span></span></pre><pre name="c362" id="c362" class="graf graf--pre graf-after--pre">on:<br>  push:<br>    branches: [ main ]</pre><pre name="74eb" id="74eb" class="graf graf--pre graf-after--pre">jobs:<br>  build:<br>    runs-on: ${{ matrix.os }}<br>    strategy:<br>      matrix:<br>        os: [ubuntu-latest, windows-latest, macos-latest]</pre><pre name="8d86" id="8d86" class="graf graf--pre graf-after--pre">    steps:<br>    - uses: actions/checkout@v4</pre><pre name="894b" id="894b" class="graf graf--pre graf-after--pre">    - name: Set up Python<br>      uses: actions/setup-python@v4<br>      with:<br>        python-version: &#39;3.10&#39;</pre><pre name="d075" id="d075" class="graf graf--pre graf-after--pre">    - name: Install pyinstaller<br>      run: pip install pyinstaller</pre><pre name="0788" id="0788" class="graf graf--pre graf-after--pre">    - name: Build executable<br>      run: pyinstaller --onefile --name index start_server.py</pre><pre name="a7eb" id="a7eb" class="graf graf--pre graf-after--pre">    - name: Upload artifact<br>      uses: actions/upload-artifact@v4<br>      with:<br>        name: ${{ runner.os }}-index<br>        path: dist/index*</pre><h3 name="fb0e" id="fb0e" class="graf graf--h3 graf-after--pre">Cosa viene creato?</h3><p name="1d48" id="1d48" class="graf graf--p graf-after--h3">Alla fine della build, trovo tre pacchetti:</p><ul class="postList"><li name="2f33" id="2f33" class="graf graf--li graf-after--p"><code class="markup--code markup--li-code">index.exe</code> per Windows</li><li name="29f7" id="29f7" class="graf graf--li graf-after--li">un binario per Linux (<code class="markup--code markup--li-code">index</code>con permessi di esecuzione)</li><li name="1eaf" id="1eaf" class="graf graf--li graf-after--li">una <code class="markup--code markup--li-code">.app</code> per macOS</li></ul><p name="50f6" id="50f6" class="graf graf--p graf-after--li">Basta scaricarli, eseguirli, e l’app parte da sola: il server si avvia, si apre il browser e tutto funziona.</p><h3 name="6ab6" id="6ab6" class="graf graf--h3 graf-after--p">L’app? Tutta inclusa</h3><p name="3413" id="3413" class="graf graf--p graf-after--h3">Nello stesso repository includo anche la cartella <code class="markup--code markup--p-code">docs/</code> con HTML, JS, immagini e dati.<br>Così l’eseguibile non serve solo lo script, ma <strong class="markup--strong markup--p-strong">tutta l&#39;applicazione web</strong>.</p><h3 name="88b4" id="88b4" class="graf graf--h3 graf-after--p">Conclusione</h3><p name="1085" id="1085" class="graf graf--p graf-after--h3">Con un piccolo script Python, un tool come PyInstaller e l’automazione delle GitHub Actions ho:</p><ul class="postList"><li name="a026" id="a026" class="graf graf--li graf-after--p">risolto i problemi legati al caricamento locale di web app,</li><li name="cef9" id="cef9" class="graf graf--li graf-after--li">creato un pacchetto eseguibile per chi non ha competenze tecniche,</li><li name="593c" id="593c" class="graf graf--li graf-after--li">automatizzato tutto il processo in pochi minuti.</li></ul><p name="dfe3" id="dfe3" class="graf graf--p graf-after--li">Il risultato è un’app accessibile con un doppio clic, da qualunque sistema operativo.</p><p name="eb15" id="eb15" class="graf graf--p graf-after--p graf--trailing"><strong class="markup--strong markup--p-strong">Doppio clic, browser che si apre, mappa servita: missione compiuta.</strong></p></div></div></section>
